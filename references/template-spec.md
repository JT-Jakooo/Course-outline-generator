## 定位与内容边界

**考点提纲** —— 不是"浓缩教材"，更不是复习资料。只做「**筛选 + 压缩 + 重排**」，
**不做任何增补**。读者拿它当"目录 + 公式索引"用；**要看讲解就去看讲义**。

用户原话：**「不要胡编乱造，要实事求是」「一切要严格按照教材的内容来」。**
用户原话（2026-09-30）：**「你在这版根据 skills 出的提纲里面加了太多根本不需要的
冗余的内容，一大段长文字，为什么我不去直接看讲义呢？提纲的重点就是提炼考点。」**

### 取舍规则（保留什么 / 删什么）

**保留** —— 实测密度参照手打提纲：Probability I Chapter 1 = **3 个条目**；
Chapter 2 整章 = **15 段**。

| 保留 | 删除 |
|---|---|
| 编号条目：`Definition` / `Theorem` / `Lemma` / `Proposition` / `Corollary` / `Remark` / `Note` / `Axiom` | `Example`（例子）—— 除非用户点名要 |
| 条目的**条件与结论** | `Exercise` / `Problem`（练习） |
| **关键公式**（尤其含 ∑ ∏ ∫ 的求和/积分式） | 动机 / 直觉 / 背景（`An informal view`、`Intuitively, …`） |
| **极短**的连接语（`Let Ω be discrete.`） | 证明的**推导过程**（结论留、过程删） |
| 作者本人的 `*` 批注 | 大段解释性段落（`The advantage of …`、`Because of this, …`） |
| 章 / 节 / 次级小标题 | 参考性表格（`Table 1: Different sample spaces`）—— 除非用户点名要 |

> 判断标准一句话：**这一行是不是"要背 / 要会用"的东西？** 不是就删。
> 宁可删多、被要求补回，也不要删少、被要求重做。

### 九条硬约束

| # | 规则 |
|---|---|
| 1 | **绝不编造**：定义/定理/命题/引理/推论/例子/编号/公式/符号必须逐条源自素材；素材缺失就**告知用户**，不用通用知识填空 |
| 2 | **只许删减，不许增补**：解释性文字**直接删除**（"压短"不够，要删干净）；**不得**新增定义、定理、例子、证明步骤、"直观理解"、"背景介绍"。自检：每句话都要能在素材里指到出处 |
| 3 | **不补全推导**：证明里省略的步骤不自行补（哪怕显然）；素材只给结论就不写证明；确需补**先问用户** |
| 4 | **编号照抄**：`Definition 1.1` / `Theorem 2.7` 原样；缺号（跳过 2.2）照缺不补；合并编号照原样 |
| 5 | **术语照搬**：素材内部说法不一致时**保留原样**，不擅自统一，不换更"规范/通俗"的措辞 |
| 6 | **不做复习型加工**：不加易错点/自测题/章末小结/考点提示/口诀；不主动加目录页、索引、符号表、公式速查表（除非用户要求）。**"提炼考点"= 删掉非考点，不是标注考点** |
| 7 | **交叉引用只写素材里有的**：`<Theorem 10.17>`、`Etc.`、`Recall`、`Note!!!`、`*注释` 等，素材没有就不造 |
| 8 | **不确定就问**：补一句/加例子/合并节/略去段的判断一律先问用户 |
| 9 | **语言与素材一致（全英文）**：笔记正文、条目名（`Definition 2.4`）、术语与连接语一律使用**素材的原语言**；本课程素材为英文讲义 → **输出全英文**，不翻译成中文，不做中英混排（数学符号与公式除外） |

> 下文所有排版规则**只改变呈现形式，不允许改变内容**；冲突时**以内容边界为准**。
> 完整版见 `SKILL.md` 的「内容边界（硬约束）」。

### 加粗的检测陷阱（Cambria Math 无 Bold 字面）

`<w:b/>` 在 Word 里对 **Cambria Math** 走"**合成加粗**"（描边加粗），因为该字体
没有 Bold 字面。后果：

- 导出的 PDF 里**不会嵌入任何粗体字体**（实测 Linear Algebra 56 页 PDF 只有
  `CambriaMath` / `DengXian` / `Wingdings-Regular`）。
- 用 pymupdf 按字体名或 `flags & 16` 检测会**一律报"非粗体"**，全篇 0 个 bold span。
- **这不是缺陷**：目视（渲染 PNG）确认标题是加粗的。判定加粗请以
  `styles.xml` 的 `<w:b/>` + 目视为准，不要以 PDF 的 flags 为准。

## 分行规则（样本实测）

**一个逻辑单元 = 一个段落**：

- 条目标题独占一段（后面紧跟正文，不并入同段）
- 每条陈述句 / 每个公式 / 每个列表项 / 证明的每个推导步骤各占一段
- 章标题、节标题各占一段；目录项各占一段
- 长句**不拆行**，作为一段整体排（Word 自动折行）

样本段落构成：纯公式段 626 / 纯文字段 434 / 空段 298 / **文字与公式混排仅 38**。

## 核心排版约定一：含公式的行用「混排段落」

样本里 `<m:nor>`（Word 公式内用引号括起来的"普通文本"）出现 **1102 次**。
作者的做法是：**把整行文字都写进公式对象，再用引号把文字变回普通文本**。

但该做法有副作用：整行变成一个数学段落（`m:oMathPara`）后，
**Word 对数学段落的分行会强加缩进** —— 实测正文行折行过早（第 1 行右侧空 186pt）
且续行缩进 72pt（看起来像居中）。

生成器对含正文文字的行改用等价的**混排段落**：文字段走普通 `w:r`、数学段走行内 `m:oMath`，
段落 `w:jc=left`。两种写法的**渲染字号实测完全相同**：

| 承载方式 | 正文字号 | 下标字号 | 折行表现 |
|---|---|---|---|
| 整行并入 `m:oMathPara` | 11.04pt | 8.04pt | ✗ 折行过早 + 续行缩进 72pt |
| **混排段落（默认）** | **11.04pt** | **8.04pt** | ✓ 占满整行 + 续行齐左 |

开关：`CFG['prose_carrier']`（`'mixed'` 默认 / `'inline_formula'` 回到样本写法）。

## 核心排版约定二：纯公式段落用 `m:oMathPara` + 显式 `m:jc`

**裸行内 `m:oMath` 且段落里没有文字是坑**：Word 把这种段落当数学段落，
按默认对齐（居中）排，段落自己的 `w:jc` 被忽略 —— 实测确认（同一段落设 `w:jc=left` 仍然居中）。
所以**纯公式段落必须包 `m:oMathPara` 并显式写 `m:jc`**。

样本自身的约定（统计每个含公式段落的 `oMathPara` 的 `m:jc`）：

| 段落类型 | left | center | right | 无 oMathPara | 结论 |
|---|---|---|---|---|---|
| 含正文文字的段落 | 138 | 48 | 0 | 107 | **左对齐** |
| 长正文段落 | 92 | 22 | 0 | 36 | **左对齐** |
| 纯公式段落 | 20 | 83 | 3 | 116 | **居中** |

生成器规则：

| 段落 | 承载 | 对齐 | CFG 键 |
|---|---|---|---|
| 含正文文字（`Let $K$ be a field, …`） | 混排段落 | `left` | `prose_jc` |
| 独占一行的纯公式（`$$...$$`） | `m:oMathPara` | `center` | `display_jc` |
| 多行分步推导（`array` / `aligned`） | `m:oMathPara` | `left` | `derive_jc` |

## 核心排版约定三：空格必须是普通空格，不能是 NBSP

`latex2mathml` 会把 `\text{}` 里的普通空格转成 U+00A0（不换行空格）。
**样本 1101 个正文 run 里 NBSP 数量为 0** —— 作者用的全是普通空格。
NBSP 会让 Word 无法在词间断行，整行只能挤在数学运算符处折断。

生成器自动把 NBSP 换回普通空格；`\quad` / `\qquad` 这类**有意**的间距
另用私有区标记保留为 NBSP，不被压掉。

## 核心排版约定四：括号必须随内容高度伸缩

LaTeX 里括号随内容自动放大；OMML 里只有 **`m:d`（delimiter）对象**才会被 Word 纵向拉伸，
普通字符 run 渲染出来是固定大小的默认括号。

| 写法 | 结果 |
|---|---|
| `(\frac{a}{b})`、`[\frac{a}{b}]`、`\{\frac{a}{b}\}`、`\left(…\right)` | ✅ 伸缩 |
| `\|\frac{a}{b}\|`、`\lvert`、`\lVert` | ✅ 伸缩 |
| `pmatrix` / `bmatrix` / `vmatrix` / `cases` | ✅ 伸缩 |
| `\langle…\rangle`、`\lfloor…\rfloor`、`\lceil…\rceil`（**加 `\left` 也一样**） | ❌ 固定大小 |
| **`\det\begin{pmatrix}…\end{pmatrix}`、`\operatorname{tr}(…)`、`f(x)`** | ❌ **完全不伸缩** |

根因（两类）：

1. `latex2mathml` 把 `\langle` `\lfloor` `\lceil` 归成 `<mi>`（标识符）而非 `<mo fence>`，
   `MML2OMML.XSL` 于是把 `⟨u,v⟩` 合并成**一个** `m:r`/`m:t`，定界符不是独立元素。
2. **函数名紧邻定界符**时，`latex2mathml` 把函数名和后面的 `(` 合并进同一个 `<m:t>`
   （如 `"det("`），`(` 同样不是独立元素 —— 实测 `\det(pmatrix)` 的括号墨迹高度
   只有行内墨迹的 **0.56 倍**（正常应 ≥ 0.9）。内容矮时看不出，内容一高就露馅。

修复（`_stretch_delims`）：① `_split_delim_runs` 把混在 run 里的
`( ) [ ] { } ⟨ ⟩ ⌊ ⌋ ⌈ ⌉ ⟮ ⟯` 拆成独立 run；
② `_wrap_stretch_delims` 取**距离最近的一对**配对（嵌套时先裹最内层），
连同中间内容包进 `m:d`（`begChr`/`endChr`）。`m:nor`（`\text{}` 正文）不动。
`|` 与 `‖` 不加入拆分集（`|x|+|y|` 里有中间 `|` run，加入会误配对）；
`(a,b]` 这类非成对写法不会被误配。

**`\big` `\Big` `\bigg` `\Bigg` 在本链路里完全无效**（`minsize/maxsize` 被 XSL 忽略），
且 `\big\langle` 会被输出成**字面文本** `\langle` —— 故预处理直接删除，
正则带 `(?![A-Za-z])` 以免误伤 `\bigcup` `\bigcap` `\bigoplus` 等。

**校验**：`selftest_formulas.py` 的定界符伸缩自检 39 例（含 3 例非成对）必须全过；
渲染级用**连通域**量测括号墨迹高度 / 行内墨迹高度（≥ 0.85）。
横向留 ±3pt 或纵向留 ±26pt 的裁剪窗会把邻居墨迹计入，制造"周期性接缝"的**假阳性**。

## 核心排版约定五：函数名必须正体（`m:sty val="p"`）

样本里 `det` / `dim` 的 run 都带 `<m:sty m:val="p"/>`（正体）。
`latex2mathml` 对多数函数名输出 `<mi>`（XSL 会给 `sty=p`），
但 `det` `lim` `limsup` `liminf` `sup` `inf` `min` `max` `gcd` `Pr` 输出的是 `<mo>`，
会被渲染成**斜体** —— `preprocess_tex` 统一改写成 `\mathrm{…}` 修正；
`\operatorname{…}` / `\operatorname*{…}` 一并改写。
正则带 `(?![A-Za-z])`，不误伤 `\supset` / `\infty` / `\bigcup`。
`\lim_{…}` 在本链路本来就是 `m:sSub`，换写法不改变下标位置。

**校验**：`selftest_formulas.py` 的"函数名正体自检"。

## 公式大小：行内小公式 vs 独立大公式

**判据是"这一行放不放得下"，不是"有没有 ∑"。**（用户 2026-09-30 提出）

| | 小公式（行内 `$...$`） | 大公式（独立 `$$...$$`） |
|---|---|---|
| 版式 | 跟文字同段、左对齐、随文字折行 | `m:oMathPara` 居中（多行推导左对齐） |
| 样本实例 | `(b) Sum up to one, i.e. Σ_{ω∈Ω} ℙ({ω}) = 1`（整行 176pt，列宽 415pt） | 编号公式 `ℙ(E) = Σ_{ω∈E} ℙ({ω})`（讲义公式 (1)）、矩阵、分段函数 |

**自动拆分（安全网）**：行内出现大运算符（`\sum` `\prod` `\int` `\lim` `\bigcup` …）
**且整行估算宽度 > 列宽 × 0.97** 时，才拆成 `正文段 → 独立公式 → 正文段`。

原因：**Word 遇到 n 元运算符会强制把折行的续行缩进到运算符位置** ——
实测行内 `\sum` 也一样（续行从 333pt 起，正常应 90pt）。
**但只有真的折行才出问题**：样本的 `(b)` 行短到不折行，作者就保持行内，
看着比另起一行干净得多。旧规则"见 ∑ 必拆"过激，已废弃。

宽度估算（`_line_width_pt`）：PIL + `C:\Windows\Fonts\cambria.ttc`（**index=1 = Cambria Math**）
逐字符 `getlength`；公式段先转近似 Unicode，二元运算符两侧各补 0.24em、大运算符放大 1.30×；
上下标宽度并入基数（偏宽 = 保守）。实测与 Word 渲染偏差 < 5%。

开关：`CFG['split_big_ops']`（默认 `True`）、`CFG['split_ratio']`（默认 `0.97`）。

### 列表块的边界间距（Prob I Ch1 逐行实测，2026-09-30）

列表不是"每项一律 8pt 段后"，而是**四档**：

| 位置 | 提纲实测 | CFG |
|---|---|---|
| 条目 / 小标题 → 列表块首项 | 25.1pt | `before_list=6` |
| 列表项之间（一级↔一级 / 一级↔二级 / 二级↔二级） | 17.5~18.6pt | `after_list_item=4` |
| 正文 → 分点块首项（`(a)` 开头） | 26.6pt | `before_label_item=10` |
| `(a)` → `(b)` 并列分点之间 | **26.4pt** | `after_label_item=12` |
| 列表块 → 下一个块 | 51.7pt | 由下一块的 `before`(36) 提供 |
| 列表块 → 普通正文 | —（提纲无此例） | `after_list_block=18` |

要点：
- **并列分点（`(a)(b)`）自成两档**：块上边界 26.6、项间 26.4，都比普通列表
  （25.1 / 18.0）大一档 —— 并列项要显得彼此独立，这就是"分点的优势"。
- **末项的下边界只在后接普通正文时才加**；后接条目标题 / 小标题时，
  它们自带 36pt 段前，块边界已经成立，末项仍用 `after_list_item`。
  这一"看下一行是什么再决定"的判定靠 `_list_flags` 预扫实现。
- **章标题后的第一个块用 `before_entry_first=10`**（不是 36pt）：
  提纲实测"章标题 → 第一条目"只有 **29.8pt**，而"正文 → 条目"是 **51.7pt**，
  一律套 36pt 会让每章开头多空 26pt。见 `_after_h1`。

## Markdown → docx 映射

| 写法 | 结果 |
|---|---|
| `# Chapter N 章名` | Heading 1（15pt 加粗，深蓝） |
| `## N.M 小节名` | Heading 2（14pt 加粗，深蓝） |
| `##### N.M.K 三级标题` | Heading 3（16pt 加粗，深蓝） |
| `#### 次级小标题`（无编号） | 12pt 加粗正文（黑） |
| `### Definition 1.1 名称` | 条目标题（12pt；编号加粗、名称常规） |
| 普通段落 | 正文 11pt |
| `- 列表项` | 一级列表（`numPr ilvl=0`；符号 x0=90、文字 x0=112、11pt） |
| `  - 子项`（缩进 2 空格） | **二级列表**（`ilvl=1`；符号 `-`、文字 x0=134、**10pt**） |
| `- (a) …` / `- (1) …` | 自带标号 → **不加符号、不缩进**（齐左 x0=90） |
| `**粗体**` | 加粗（公式行内也支持，落成 `<w:b/>`） |
| `~~删除线~~` | 删除线（内部可含 `$...$`，公式也会被划掉） |
| `*注释`（星号紧跟文字） | 正文段落，星号保留 |
| `$...$` | 行内**小公式**；所在段落为混排段落，左对齐；**整行放得下就保持行内** |
| 独占一行的 `$$...$$` | 纯公式行（`m:oMathPara`），**大公式**，居中 |
| `$$` 多行块 | 每行各成一条独立公式（可用来手动分行） |
| 含大运算符的正文行 | **仅当整行估算宽度 > 列宽×0.97** 才拆：正文 → 独立公式 → 正文 |
| `\| a \| b \|` + `\|---\|---\|` | Word 表格（固定列宽 + booktabs 框线；单元格内支持 `$...$`，整格只有一个公式时用 `oMathPara` 承载） |
